Each Practice session and Race now has its own Track setup, Network connections are simpler across Bluetooth, LapRF, and RotorHazard, and mobile navigation is much smoother.

### What's New
- **Per-session and per-race tracks**: Set up gate order, Start / Finish, and timing rules independently inside each Practice session and Race instead of sharing one global track.
- **Separate LapRF 8-Way Network and USB modes**: Choose between **LapRF 8-Way (Network)** and **LapRF 8-Way (USB)** directly in **Network**.
- **Bluetooth Hub pairing controls**: Pair, reconnect, cancel, or forget a SlapRF Bluetooth Hub directly from **Network**.
- **Automatic LAN mode on headless Raspberry Pi**: Running `slaprf` over SSH or as a service on Linux without a display now enables LAN access and powers on Bluetooth automatically.

### Improvements
- **Per-timer signal calibration**: Calibrate and fine-tune thresholds per timer in **Signals**, with pilot VTX channels shown right on each pilot pill.
- **Smoother mobile navigation**: Swipe across tabs in the same order as the bottom bar (including over the Network graph and Simulator track) with natural flick physics and smooth drawer animations.
- **Cleaner Network connection bar**: Switch timing systems inline on **Network**, pick discovered LAN or USB timers from a single dialog, and sign in to password-protected RotorHazard timers when prompted.
- **Compact mobile Simulator table**: Redesigned the **Simulator** boards list on phones with status LEDs and icon actions so it fits without horizontal scrolling.

### Fixes
- **Android app updates**: Updating the Android APK now loads the new UI immediately instead of serving cached files from the previous version.
- **Linux Bluetooth reconnects**: Fixed an issue where reconnecting to a Bluetooth Hub after disconnecting could fail until restarting the app.
- **Mobile Signals scrolling**: Fixed frame drops when scrolling the timer list during live telemetry and improved tapping numeric fine-tune inputs.
- **Flasher port selection**: **Read config**, **Flash**, and **Erase** now consistently prompt you to choose a USB port.

> **Firmware compatibility**: Existing `v0.0.8` or newer XIAO ESP32-C5 timers work without reflashing.
> **API note**: REST `/v1` hardware and track endpoints were reorganized by transport and session; see `/docs/specs/openapi.yaml` if you use custom scripts.
