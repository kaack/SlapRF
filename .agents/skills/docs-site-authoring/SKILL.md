# Authoring & Building `docs-site/` (Hugo + Hextra)

The SlapRF documentation site (`https://slaprf.app/docs/`) lives in `docs-site/` and builds with **Hugo Extended `0.170.1`** via `cmd/build-docs`. Pair this skill with `technical-writing-ste` whenever writing or editing Markdown content.

## 1. Site Structure

- `docs-site/content/`:
  - `_index.md`: Docs landing page
  - `getting-started/`: `installation.md`, `architecture.md`
  - `hardware/`: `parts-and-assembly.md`, `flashing.md`, `status-leds.md`
  - `journeys/`: `practice.md`, `multi-gate-splits.md`, `race-events.md`, `external-timers.md`
  - `reference/`: `ui-reference.md`, `troubleshooting.md`, `api-reference/{rest,async}.md`
- `docs-site/layouts/`:
  - `_partials/theme-toggle.html` & `_partials/custom/head-end.html`: Custom 3-way (`Light` / `Auto` / `Dark`) theme switcher.
  - `_partials/custom/flasher-modal-template.html`: Shadow-DOM mount for the standalone WebSerial Firmware Flasher.
  - `shortcodes/`: Custom Hugo shortcodes (`themed-image.html`, `web-flasher.html`, `api-spec-viewer.html`, `led-pattern.html`, `yes.html`, `no.html`).
- `docs-site/static/`:
  - `images/`: Logos and paired light/dark hardware diagrams.
  - `specs/openapi.yaml` & `specs/asyncapi.yaml`: Interactive REST & WebSocket API specs.
  - `js/docs-flasher.{js,css}` & `firmware/*.bin`: Generated by `cmd/build-docs` (gitignored).

## 2. Custom Shortcodes & Theme Rules

1. **Theme-Aware Diagrams & Screenshots (`themed-image`)**:
   Every diagram or screenshot embedded in `docs-site/content/` should provide both a Light image and a Dark image (`#0f172a` dark-slate background for hardware illustrations so dark mode never renders bright white rectangles):
   ```markdown
   {{< themed-image light="images/xiao-c5-board-guide.jpg" dark="images/xiao-c5-board-guide-dark.jpg" alt="Seeed Studio XIAO ESP32-C5 Board Guide" >}}
   ```
2. **Embedded WebSerial Firmware Flasher (`web-flasher`)**:
   Renders the inline `Open Firmware Flasher` trigger wired to `docs-flasher.js`:
   ```markdown
   {{< web-flasher >}}
   ```
3. **Interactive API Spec Viewers (`api-spec-viewer`)**:
   Used in `reference/api-reference/rest.md` and `async.md`:
   ```markdown
   {{< api-spec-viewer type="openapi" >}}
   {{< api-spec-viewer type="asyncapi" >}}
   ```
4. **LED Blink Previews & Checkmarks**:
   Use `{{< led-pattern ... >}}` on `hardware/status-leds.md` and `{{< yes >}}` / `{{< no >}}` in capability matrices.
5. **3-Way Theme Switcher Default (`Auto`)**:
   `theme-toggle.html` + `head-end.html` must default to **`Auto`** (tracking OS/browser `prefers-color-scheme: dark` live) whenever no explicit `"light"` or `"dark"` user override is stored.

## 3. Building & Local Preview

`cmd/build-docs` compiles `docs_flasher.ts` + Shadow-DOM CSS into `docs-site/static/js/`, stages firmware `.bin` files, runs Hugo, and strips unused stock Hextra favicon/manifest clutter:

```bash
# 1. Stage flasher bundle & verify clean production Hugo build into ./_site/docs
go run ./cmd/build-docs -web ./web -docs ./docs-site -out ./_site/docs -base-url /docs/ -skip-firmware

# 2. Start live-reload Hugo preview server on http://127.0.0.1:1313/docs/
cd docs-site && hugo server -D --port 1313 --bind 127.0.0.1 --baseURL http://127.0.0.1:1313/docs/ --disableFastRender
```

### Deployment Note (`docs.yml` vs `pages.yml`)
- Pushing changes under `docs-site/**` to `main` automatically runs `.github/workflows/docs.yml` (~35s), which builds `./_site/docs` with `-skip-firmware` (since `/firmware/*.bin` already lives at the `github-page` root `/docs/firmware/`) and updates `/docs/docs/` on the `github-page` branch.
- If you also modified `web/src/` code shared by `docs_flasher.ts` (`esp_flasher.ts`, `esptool_flasher.ts`), trigger `docs.yml` (`gh workflow run docs.yml`) or let `pages.yml` deploy both the app and docs together.
